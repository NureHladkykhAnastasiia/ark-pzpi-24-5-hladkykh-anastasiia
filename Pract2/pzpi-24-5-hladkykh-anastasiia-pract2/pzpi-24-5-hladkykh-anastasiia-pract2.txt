  2 ЗАВДАННЯ
  Вивчити методи рефакторингу з книги Мартіна Фаулера «Refactoring. Improving the Design of Existing Code» та застосувати три з них до власного програмного коду, написаного в курсових і лабораторних роботах. Для кожного методу визначити проблему в початковому коді, навести код до і після рефакторингу, пояснити переваги отриманого рішення. Підготувати презентацію, відеодоповідь і звіт.


  3 ОПИС ВИКОНАНОЇ РОБОТИ
  3.1 Вибір методів рефакторингу
  Для роботи обрано курсовий проєкт з дисципліни «Бази даних»: десктопну систему управління онлайн-магазином косметики на C# (Windows Forms) з базою даних MySQL. Проєкт містить головну форму Form1.cs з кількома вкладками та допоміжні форми для створення і редагування записів (OrderForm.cs, ManufacturerForm.cs та інші).
  Для рефакторингу обрано три методи, кожен з яких розв'язує конкретну проблему проєкту:
* Preserve Whole Object (Збереження цілого об'єкта, с. 188) для передачі даних у форму редагування;
* Encapsulate Downcast (Інкапсуляція низхідного перетворення типу, с. 202) для приведення типу джерела даних у комбобоксі;
* Form Template Method (Формування шаблонного методу, с. 226) для повторюваних методів видалення записів.
  Сторінки вказано за предметним покажчиком книги Фаулера.
  
  3.2 Метод 1: Preserve Whole Object
  Проблема. У Form1.cs методи редагування (EditManufacturer, EditWarehouse, EditSupplier та інші) витягують із вибраного рядка DataGridView від 5 до 9 окремих значень і передають їх у конструктор дочірньої форми окремими аргументами. Конструктор ManufacturerForm приймає 9 параметрів. Через це легко переплутати порядок аргументів, а при додаванні нового поля в таблицю доводиться змінювати сигнатуру конструктора і всі місця його виклику.
  Рефакторинг. Дані виробника переносяться в окремий клас ManufacturerData. Розбір рядка таблиці інкапсульовано в статичному методі FromRow. Конструктор ManufacturerForm приймає один об'єкт. Старий конструктор з 9 параметрами видаляється.
  Переваги. Метод EditManufacturer коротший, а виклик форми зводиться до одного аргументу. Додавання поля вимагає змін лише в класі ManufacturerData і в FromRow. Перевірка типів переходить від порядку позиційних аргументів до іменованих властивостей.
  Код наведено в розділі В.1 додатка В.
  
  3.3 Метод 2: Encapsulate Downcast
  Проблема. У OrderForm.cs, в обробнику BtnAddProduct_Click, властивість DataSource комбобокса (тип object) приводиться до DataTable вручну:
  
   var productData = (DataTable)cbProduct.DataSource;
  
  Компілятор не перевіряє цей крок. Якщо тип джерела даних зміниться, програма завершиться з InvalidCastException під час роботи. Знання про внутрішній тип джерела розкидане по обробнику кнопки.
  Рефакторинг. Приведення винесено в метод GetProductTable, який повертає DataTable через оператор as. Оператор as не викидає виняток, а повертає null. Обробник перевіряє результат і показує користувачу зрозуміле повідомлення.
  Переваги. Знання про тип джерела зосереджено в одному місці. Обробник працює з DataTable без приведення. Помилка виводиться як повідомлення, а не як аварійне завершення.
  Код наведено в розділі В.2 додатка В.
  
  3.4 Метод 3: Form Template Method
  Проблема. У Form1.cs методи DeleteManufacturer і DeleteWarehouse (а також DeleteIngredient, DeleteCertification, DeleteCustomer, DeleteBrand, DeleteCategory, DeleteSupplier) повторюють один і той самий алгоритм: перевірка вибору рядка, запит підтвердження, видалення запису в БД, повідомлення і перезавантаження таблиці. Відрізняються лише назва сутності, колонка з назвою, таблиця, колонка з ідентифікатором і метод оновлення.
  Рефакторинг. Створено абстрактний клас ReferenceDeleteTemplate. Його метод DeleteSelected() задає незмінну послідовність кроків. Змінні частини оголошуються як абстрактні властивості та метод Reload(). Конкретні класи ManufacturerDeleter і WarehouseDeleter перевизначають лише ці частини.
  Переваги. Алгоритм видалення описано в одному місці. Додавання нового довідника вимагає лише підкласу з шістьма властивостями. Зміна тексту підтвердження або порядку кроків виконується один раз для всіх сутностей.
  Код наведено в розділі В.3 додатка В.
  
  3.5 Проблеми, знайдені під час роботи
  Під час аналізу коду знайдено такі проблеми, які не входять до трьох методів, але їх варто виправити:
* у EditManufacturer() читається колонка «Адреса», якої немає у запиті LoadManufacturers(). Через це під час натискання «Редагувати» виникає виняток, і метод переходить у catch;
* SQL-запити в Form1.cs та OrderForm.cs формуються конкатенацією рядків (наприклад, $"DELETE FROM Orders WHERE order_id = {orderId}"). Це створює ризик SQL-ін'єкцій, для усунення якого потрібні параметризовані запити;
* рядок підключення з паролем записано безпосередньо в DatabaseHelper.cs. Для усунення цієї проблеми пароль слід винести в конфігураційний файл або змінні середовища.

  У ході практичної роботи розглянуто три методи рефакторингу з книги Мартіна Фаулера: Preserve Whole Object, Encapsulate Downcast та Form Template Method. Кожен метод застосовано до реального коду курсового проєкту. Для кожного визначено проблему, описано рефакторинг і його переваги. Отримано навички аналізу коду на предмет дублювання, зайвих параметрів і неявних приведень типу, а також навички оформлення рефакторингу у вигляді блоків «до» і «після». Під час аналізу виявлено помилку з колонкою «Адреса», ризик SQL-ін'єкцій і збережений пароль, які стануть предметом подальших змін у проєкті.

   1  public abstract class ReferenceDeleteTemplate
    2  {
    3      protected readonly DatabaseHelper db = new DatabaseHelper();
    4
    5      protected abstract DataGridView Grid { get; }
    6      protected abstract string EntityGenitive { get; }
    7      protected abstract string EntityNominative { get; }
    8      protected abstract string NameColumn { get; }
    9      protected abstract string TableName { get; }
   10      protected abstract string IdColumn { get; }
   11      protected abstract void Reload();
   12
   13      public void DeleteSelected()
   14      {
   15          if (Grid.SelectedRows.Count == 0)
   16          {
   17              MessageBox.Show($"Виберіть {EntityGenitive} для видалення!", "Увага",
   18                  MessageBoxButtons.OK, MessageBoxIcon.Warning);
   19              return;
   20          }
   21
   22          string name = Grid.SelectedRows[0].Cells[NameColumn].Value?.ToString() ?? "";
   23          var confirm = MessageBox.Show($"Видалити {EntityGenitive}: {name}?",
   24              "Підтвердження", MessageBoxButtons.YesNo, MessageBoxIcon.Question);
   25          if (confirm != DialogResult.Yes) return;
   26
   27          int id = Convert.ToInt32(Grid.SelectedRows[0].Cells["ID"].Value);
   28          db.ExecuteNonQuery($"DELETE FROM {TableName} WHERE {IdColumn} = {id}");
   29          MessageBox.Show($"{EntityNominative} видалено!", "Успіх",
   30              MessageBoxButtons.OK, MessageBoxIcon.Information);
   31          Reload();
   32      }
   33  }
